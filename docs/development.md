# Developing FlickGrove

Build and test the project from the repository root. For first startup, see the [root README](../README.md).

## Browser and development

HTML preview links and tabs can navigate inside the sandbox. Close and parent navigation skip those internal history steps, keeping the outer controls responsive; native browser Back still traverses the iframe history. This preview navigation uses the Navigation API supported by Safari 26.2+ and current Chrome.

Open Orc trees are grouped automatically by the registered GitHub/Forgejo remote owner, ignoring host and case (for example GuionAI/guionai becomes **guionai**). Personal owners follow the same rule. Owner names sort alphabetically; unknown, local or missing remotes appear under **Ungrouped** last. Only the derived owner reaches the browser. A failed catalogue read uses Ungrouped until a successful refresh; the remembered organization is retained.

The sidebar title selects an organization with an open Orc tree by project repository owner, including trees in Recent activity; the selection is remembered in this browser for the instance. Creating a session selects its project's organization. Recent activity includes trees from every organization. Opened shows the selected organization’s remaining trees. Its heading collapses or expands those trees, with the choice remembered per organization. On desktop, hovering an Orc or member previews its latest available detail without changing the selected session; moving away restores the selected detail and clicking switches sessions while restoring the saved reading position. Opened follows the service snapshot order; earlier browser-saved manual order is ignored. Members stay with their owner, and mobile retains swipe Close.

Close waits for native `thread/closed`, after Codex has shut down that thread and released its writer ownership, before removing the Orc or Worker from Grove. An unsubscribe acknowledgement alone is insufficient. Timeout/disconnection remains visible and retryable with an unconfirmed outcome; other threads in the shared Grove-owned app-server keep running. Grove starts its own process with zero idle unload delay and never changes user configuration or the system daemon.

Spec **#5082**: **Recent activity** appears above Opened and offers 1h, 4h, 1d and 1w windows, remembered in this browser. An Orc or any owned member working, sending a message or finishing updates its tree's activity; a working or stopping tree remains visible. Trees are ordered by name, so new activity does not rearrange the list. Activity is retained through restart for newly observed work, and old sessions have no fabricated activity time. Each open tree appears in at most one section; when recent activity expires it returns to Opened for its selected organization. Switching organizations keeps the current detail and draft. Close a tree using Option/Alt+X or mobile swipe, with the existing guarded recovery flow.

Shortcuts: Up/down wraps within the focused recent list or visible Opened section. **Cmd/Ctrl+1–9** opens the first nine visible sessions; **Option/Alt+J/K** cycles next/previous. Both use recent activity and expanded members followed by the selected organization’s Opened trees. Right expands an Orc or enters its first Worker; left collapses an Orc or locates a Worker’s parent. Desktop arrow navigation switches the persistent detail and highlights only that session; in the mobile list, Enter opens the navigation item. E toggles Workers, N opens creation with project-search focus, I focuses the Orc composer, Escape dismisses the top visible layer, and ? shows help. Ordinary arrows retain text-editing precedence; IME composition and foreground panels (creation, settings, skill search and other temporary surfaces) block session shortcuts. **Option+S** on Mac / **Alt+S** elsewhere opens skill search for the editable Orc, using the physical S key and preserving the draft and caret/selection even outside Composer focus. Mobile has a skill icon beside Add images. IME composition, other modifier combinations and foreground panels retain their own input. `$` is ordinary draft text and never opens search. Tab or Enter selects the current skill and inserts its exact `$skill-name` at the saved selection; Esc or Back restores the draft and selection. Tab does not traverse page controls; Enter sends, Shift+Enter inserts a newline. Send remains clickable and Stop has its own control while Orc is working. Tree closure produces a three-second toast.

On mobile, browser Back, the on-screen return and Esc unwind the same visible layers: a question card, dialog, skill search, quota popover, title edit or transient surface closes before its underlying conversation. A Worker opened from an Orc returns to that Orc; a detail opened directly from the list returns to the list. List switching first dismisses active transient layers, then replaces the entire conversation journey with one detail that returns to the list, including switches from a nested Worker. Forward restores valid targets; refresh restores detail with a list return target. Closed targets resolve to a valid parent or list. The temporary Sidebar drawer participates in this same foreground hierarchy; closing it preserves the underlying detail. Returning from detail to the list opens navigation; the root remains escapable without a permanent history sentinel. Desktop detail has no Close or collapse action; Escape dismisses a foreground layer or expanded question card and otherwise retains the current conversation. Returning preserves drafts, scroll and expansion and does not send, Stop or Close an agent.

A small circular Lucide **Jump to bottom** icon button appears at the lower-right of the Orc/Worker conversation when reading above the bottom. Clicking scrolls to the end without enabling automatic following; short conversations and the bottom hide the button. Sending a message or answering a Question positions the sent input near the top once. Temporary space below it is consumed by subsequent content; a short reply does not collapse the remaining space and move the reader. Moving upward safely reclaims available space. It stays within the transcript, above Composer or the Worker footer.

Chrome notification permission is requested at first pointer interaction. Notifications cover only new Orc user-question batches, explicit Orc user handoffs waiting for your next instruction, and final Orc execution failures. Ordinary idle transitions, member events and automatic retries stay silent. A handoff is published only after its marked turn succeeds with no pending work or questions; further input, delegation, Stop or failure cancels it. The Orc-only `orc_handoff` tool accepts a nonempty result `summary` up to 300 characters and returns a pending intent for the current turn; repeated calls merge, and a cancelled intent cannot be rearmed in that turn. It neither sends a message nor stops/closes any session. Fixed role guidance applies even with a customized Orc prompt.

Notifications require the page to be open and permission granted; browser/OS settings control actual display. Reading the corresponding Orc in a focused, visible page suppresses notifications. Initial load, refresh, server restart and reconnect establish a baseline without replaying old events. Clicking opens the original Orc. Multiple tabs/devices observe independently; closed-page or offline delivery is not guaranteed. Install the PWA through Chrome or the progressive install action. Its service worker caches the built shell/fonts, never API responses. Browser sessions use an HttpOnly cookie; agent credentials remain server-side. The browser can retain local conversation and draft caches.

For development, start a local backend, then run `bun run dev`. The Vite API proxy targets port 4318; development does not install a service worker.

Instance controls use an authenticated, same-origin browser session. The build records its repository commit and tracked dirty state; startup compares that record with the backend checkout and fixes the displayed commit only when both are clean and match. Missing metadata, dirty tracked files, or a mismatch produce an unknown version. Existing browser-cached assets can differ from the server's built assets. MCP reload is available only while shared work is idle: Codex acknowledges a refresh request, while each open Pi session replaces its MCP connections using its own project configuration; partial or uncertain outcomes are reported. Reload does not update skills, models, instructions or application code.

Restart also requires all shared work and pending deliveries to be idle. On Linux, Grove identifies its own same-user systemd service from its cgroup and verifies the user bus owner, service name, main process and full cgroup before requesting a restart. Ambiguous, unsupported or mismatched identities are unavailable. On macOS, only the current `io.guion.flickgrove` LaunchAgent is supported. A submitted manager request has an unknown outcome until the browser observes a new process identity, and is never replayed automatically. If the manager request does not restart the process, admission stays blocked until the instance is restarted externally. This does not pull, build or deploy code. Manager behavior is covered by simulated fixtures, not live service tests.

```sh
bun run test
bun run typecheck
bun run format:check
bun run lint
bun run build
GROVE_TEST_AUTH_STUB=1 bun run test:browser
```

Browser tests build their own assets under `.scratch/flickgrove-browser/assets` and use installed Chrome with isolated profiles. `GROVE_TEST_AUTH_STUB=1` enables synthetic sign-in for the default browser fixtures; authentication-specific tests use their own isolated setup. All test state, Codex homes, credentials and project paths are temporary or synthetic. No test uses installed user credentials or changes the real project registry. Workspace/FakeRuntime, same-origin Chord/WebSocket, shared multi-thread SDK fake wire and real stdio MCP seams verify ownership, answers, defaults, outages, Stop and usage without paid calls. The preview server in `tests/design-serve.ts` exposes fixture controls only in tests, never the production handler.

## UI foundation

Desktop session creation uses N; ? opens shortcut help. A standard shadcn-svelte Sidebar holds the session tree; offcanvas collapse releases its width. The current organization selector and New session Plus sit in Sidebar.Header. Cmd+B / Ctrl+B or the persistent detail Trigger toggles navigation, including from Composer without losing its draft or caret. Desktop defaults open and remembers the origin-local boolean; mobile starts with a closed Sheet drawer and keeps its temporary state separate. Selecting dismisses the drawer; returning to the list reveals it. There is no full-width top bar or global session total. Quota rings/percentage and global Settings share the existing detail metadata row, above the editable title, and remain available without detail. Orc roots retain snapshot order and show project, work state, input needs and current total/working Worker counts. Worker navigation appears under each tree in Opened or Recent activity, including on mobile; return to the list to open a Worker. Workers default to collapsed and use indented, small titles clamped to two lines. With detail open, its session is the only highlighted row. On the mobile list, a single keyboard navigation marker locates the item to open. Execution state remains separate. Mobile uses the Sidebar Plus for creation.

Layout authority: spec **#4467**. Sidebar components come from the [official vega registry](https://shadcn-svelte.com/registry/styles/vega/sidebar.json) (`shadcn-svelte` CLI 1.7.0, retrieved 2026-10-22). Only used Sidebar/Sheet/Tooltip sources are included. Grove replaces default cookie persistence and the component keyboard listener with origin-local preference storage and its guarded application handler, aligns the breakpoint to 700px, and routes the temporary Sheet through existing foreground history. The registry requires Bits UI ^2.20.0; it was updated with `bun add -d` in this workspace (resolved 2.20.0). Existing Lucide 1.50.0 supplies the used icons. No new UI library was introduced. The mobile Sheet retains the one business tree with `forceMount`; closed content is hidden/inert and its scroll lock is disabled, preserving tree state and keyboard navigation. Returning to the list replaces its history entry so Forward remains usable.

The frontend uses project-owned shadcn-svelte components (Bits UI), Lucide icons and a compact dark workbench theme. Read [DESIGN.md](../DESIGN.md) before changing the component layer. Ordinary buttons do not retain visible focus rings after pointer actions. No compact-tree Penpot board exists; screenshots assess rendered usability. Browser checks use 1440px and 390px Chrome; real Android/PWA soft keyboards and iOS back gestures need device acceptance.

Images/questions authority: **spec #3284, tickets #3285–#3288**, now under single-host ADR 0002. Isolated images/questions tests save actual 1440px/390px screenshots to `.scratch/flickgrove-images-questions/screenshots/`; no matching Penpot board or real-phone keyboard verification is claimed.

Directory-branch authority: **spec #3301, tickets #3302/#3303, design #3295**. Isolated temporary Git/worktree, real Chord and browser checks cover changes, deduplication, failure recovery and navigation. Actual 1440px/390px long-branch/Worker screenshots live in `.scratch/flickgrove-directory-branch/screenshots/`; no matching Penpot board exists.
